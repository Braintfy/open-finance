## v0.40.0 — условное форматирование и вид колонок

- **Условное форматирование + вид колонок «Мой магазин» (v0.40.0)** — `src/lib/blocks/catalog/unit-my-store-table.tsx`. Модалка `ColumnEditDialog` переписана на **вкладки** (`Основное/Вид/Числа/Итоги/Данные`, shadcn `Tabs`). Новые поля `Column` (все optional, jsonb, без миграций БД): `color` (акцент-ключ из `ACCENT_KEYS`, 9 пресетов), `fillCells`, `outline`, `align`, `headerBold`, `scale {palette: greenRed|redGreen|heat, min/mid/max: number|null}`, `prefix`, `suffix`, `note`, `aggregate: none|sum|avg|min|max|count`. **Хелперы (module-level, pure):** `getColumnAccent`/`ACCENT_STYLES` (тинты theme-aware ТОЛЬКО литералами — Tailwind purge'ит `bg-${k}-50`!), `outlineStyleFor(col, edge?)` (inline-border, box-sizing держит ширину), `scaleTextColor(value, scale, stat)` (3-стоповая RGB-интерполяция с якорем `mid`→0.5; null min/mid/max = авто из `stat`), `applyAffix`, `alignJustify`/`alignText`, `aggregateOf`/`effectiveAggregate`/`AGG_META`. **Цветовая шкала = ТОЛЬКО цвет текста** (не фон/не бары — по решению пользователя), применена во всех точках показа числа (number/formula/per-cell/Excel-cell); перекрывает `+/−` tone, но не ошибку. **Перф-инвариант сохранён:** `scaleStats` (colId→{min,max}) считается в родителе ТОЛЬКО для колонок со `scale`; нет шкал → **стабильный пустой ref `EMPTY_SCALE_STATS`** → `React.memo(MyStoreRow)` + виртуализация v0.38.0 не страдают (новый проп строки один — `scaleStats`). **`HeaderCell`/`BodyCell` → `cn()` (twMerge)** + проп `accentStyle` (мерджится последним в inline style). **Итоги теперь конфигурируемы:** `totals` считает агрегат per-column (был захардкожен под `revenueMonth/profitMonth/stock/marginRetail`); миграция в `parseConfig` (`LEGACY_AGGREGATES`) проставляет старые агрегаты конфигам без `aggregate` → поведение не меняется; **выходные ключи паблишера (`totalRevenue/totalProfit/avgMargin/stockTotal`) сохранены** через `totals.agg[id] ?? 0` (не ломать `@`-привязки). **XLSX-адаптер `import-export/adapters/my-store-table.ts`:** экспорт `_meta.columns` через **spread `...c`** (сохраняет все поля + будущие), импорт читает новые поля обратно (zod в `parseConfig` валидирует). **Грабля:** `typeof v === 'string' ? … : v != null` для text-count — НЕ сравнивать `number !== ''` (TS сужает else-ветку до `number`, TS2367).

## v0.39.0 — Excel-режим (per-cell формулы, override формульных колонок, знаки после запятой)

- **Excel-режим блока «Мой магазин» (v0.39.0)** — `src/lib/blocks/catalog/unit-my-store-table.tsx`. Тоггл `config.excelMode` (кнопка `Excel` в шапке, персистится) включает sheet-style редактирование любой ячейки — портирован проверенный UX блока «Данные» (custom.data v0.23.x). **Ключевой контракт: per-cell формула = строковое значение `row.values[colId]`, начинающееся с `=`** (тот же `cell.v`-контракт, что и в custom.data; XLSX-адаптер `import-export/adapters/my-store-table.ts` уже её сохраняет/читает — раньше она НЕ вычислялась, показывала 0). Переменные — id колонок ТОЙ ЖЕ строки + `vatPct`/`taxRatePct`, движок — общий `evalRowFormulas` (не A1, как у custom.data — My-Store-формулы row-relative по id, поэтому drag-fill копирует строку формулы как есть). **`computeRowValues`** (единый helper строки/агрегатов) детектит `=`-строки в не-формульных колонках → `effectiveFormulas = {...formulasMap, ...cellFormulas}` per-row. **`isCellFormulaValue` НЕ type-guard** (`: boolean`, не `v is string`) — иначе TS сужал false-ветку до `number` и ломал `raw===''` для text-значений. **Единый `EditSession`** (один `draft` между inline-input ячейки и formula bar) + `dirty`-флаг (commit пишет, только если был ввод → проход Tab'ом не затирает привязку пустым draft). Паттерн фокуса/каретки 1:1 с custom.data: `cardRef`-smart-blur (focus внутри блока → не коммитим; picker открыт → `pickerCellRef.current` → не коммитим), `useLayoutEffect`+`pendingCaretRef` (восстановление каретки после programmatic-вставки), focus-эффект по `navFocusRef`+`data-cell-input="rowId|colId"` (scroll-into-view для виртуализации, rAF-ретрай пока строка не смонтируется). **Перф сохранён:** активная ячейка и formula bar — единственные, кто ре-рендерится на keystroke (`activeColId`/`sessionDraft` = null у неактивных строк → `React.memo` бейлит); все session-колбэки стабильны (deps на стабильных колбэках). **Редактируются ЛЮБЫЕ ячейки, включая формульные КОЛОНКИ** (это была главная цель — импортированные формульные колонки): клик по формульной ячейке показывает действующую `col.formula` и даёт **per-cell override** (формула/литерал ТОЛЬКО для этой строки) в `row.values[colId]`; пустой ввод или совпадение с `col.formula` → override снимается. `computeRowValues`: `=`-override → `cellFormulas` (перекрывает column-formula в `effectiveFormulas`); литерал-override на формульной колонке → `manual` + удаление её формулы из `effectiveFormulas` (литерал побеждает); зависимости считаются через граф `evalRowFormulas` (зависимые колонки строки пересчитываются от override). **Обычный режим без изменений**: ячейка-формула read-only (computed + `fx`); формульные колонки column-driven. **БД:** override персистится в `row.values` (jsonb) как обычная строка/число — без миграций; XLSX-экспорт-адаптер отдаёт override, а не общую `col.formula`. **Знаки после запятой (v0.39.0):** числа `0,5` не округляются до `1` — настройка `config.decimals` (блок: поповер «Параметры», `Авто/0/1/2/3`) + per-column `Column.decimals` (в настройках колонки). Резолвер `resolveDecimals(col, blockDecimals)` (col → блок → null=«Авто»); `formatNumber`/`formatCellValue` приняли параметр `decimals` (число → `maximumFractionDigits:N` через Intl, перекрывает округление «копеек»; целые без дробной части — одна настройка ок для мелких цен и крупных сумм). Прокинуто во ВСЕ места показа (totals/preview в родителе, `MyStoreRow` через проп `blockDecimals`, `MyStoreNumberCell`/excel-cell/formula-display); round-trip в XLSX-`_meta`. **Баг «осиротевших» значений формульных колонок (фикс, та же v0.39.0):** при смене типа колонки `money→formula` (через `ColumnEditDialog` type-select) или повторном импорте в `row.values[formulaColId]` остаются СТАРЫЕ сырые числа; ранняя версия override-логики трактовала любое непустое значение формульной колонки как литерал-override → оно затеняло формулу (`цена1мг=7500` вместо `=tsena1gr/1000→7.5`, «переключалось» при кликах). **Правило: per-cell override ФОРМУЛЬНОЙ колонки — ТОЛЬКО `=`-строка; сырые числа в row.values формульной колонки ИГНОРИРУЮТСЯ (осиротевшие).** Согласовано в `computeRowValues`, `draftForCell` (показывает формулу, не старое число), `writeSession` (литерал → `=N`; пусто/совпало с col.formula → delete override + чистка), excel-cell display, XLSX-export. **`computeRowValues`+`isCellFormulaValue` вынесены в чистый модуль `src/lib/unit-economics/my-store-compute.ts`** (структурные типы `MyStoreComputeColumn/Row`), тест `scripts/test-my-store-compute.ts` (15 кейсов: осиротевшее число игнор, `=`-override, проброс зависимостей override→зависимая колонка). **Cell-pick (фича):** в Excel-режиме при редактировании формулы (`pickMode=activeIsFormula`) клик по НЕ-identity ячейке вставляет id её колонки в формулу (`onCellPick`→`insertIntoDraftWithSession(colId,true)`), а не активирует; неактивная ячейка-кнопка держит фокус через `onMouseDown preventDefault`, каретка — `useLayoutEffect`/`pendingCaretRef`; pick-таргеты подсвечены (`cursor-cell ring-sky`). `pickMode` стабилен пока draft — формула → `React.memo` строк не страдает. Nav: Enter↓/Shift+Enter↑/Tab→/Shift+Tab←/Esc (включает identity + формульные колонки). **Грабли:** (1) `isCellFormulaValue` НЕ type-guard; (2) при привязке активной ячейки через picker — обязательно `setSession(null)` в onSave (иначе commit перетёр бы свежую привязку); (3) привязка (`привязать`) скрыта для identity и формульных колонок (`activeAllowsBinding`).

## v0.38.0 — перформанс таблицы и Excel-протяжка (drag-fill)

- **Перформанс блока «Мой магазин» + Excel-протяжка (v0.38.0)** — `src/lib/blocks/catalog/unit-my-store-table.tsx`. Лаги на 100+ строках были от: (1) рендера ВСЕХ строк, (2) per-cell подписки `LinkableNumberCell` на стор (`useAllBlockValuesFlat` пересобирает всю мапу в КАЖДОЙ ячейке), (3) `computedRows` на весь `liveValues` (пересчёт всех формул на любой publish), (4) отсутствия мемоизации строк. **Фиксы (паттерн, переиспользовать в других тяжёлых таблицах):** ① **виртуализация** — ручное окно по `scrollTop` (фикс. `ROW_H=30`, порог `VIRTUALIZE_THRESHOLD=60`), спейсеры сверху/снизу, sticky-шапка/«Итого» вне окна; ② **`React.memo` строки** `MyStoreRow` — сама считает значения через `computeRowValues` (единый helper для строки и агрегатов), ре-рендер только при смене своего `row`; ③ **стабильные row-колбэки** через `configRef`/`onConfigChangeRef` (persist + updateRow* читают `configRef.current`, deps `[persist]`); ④ **узкая зависимость от стора** — `boundSig` (сигнатура разрешённых block_ref-привязок) → `boundByRow` (deps `[boundSig]`, eslint-disable) → `computedRows`; чужой publish/печать не пересчитывают таблицу; ⑤ **dumb-ячейка `MyStoreNumberCell`** (НЕ подписывается на стор; значение/формат пропсами) с **локальным `draft` (commit на blur/Enter)** → печать не дёргает persist/ре-рендер; модалка привязки (`UnitCellBindingDialog`) поднята в блок (одна, через `pickerCell`). **Drag-fill (task 2):** fill-хэндл (`data-fill-handle`) в углу number/text ячеек, `data-fill-row={absIdx}` на строке, **document-level pointer listeners** (не pointer-capture — переживают авто-скролл/виртуализацию), копирует значение+привязку по видимому порядку → `persist({rows})`. Формульные/identity — без хэндла. Bulk-fill в `ColumnEditDialog` остаётся для «все строки». **Грабля:** dumb-ячейка должна флашить `draft` на unmount (строка ушла из окна) — иначе теряется ввод.
