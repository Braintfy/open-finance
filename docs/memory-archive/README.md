# Memory Archive — Open Finance

> Эта папка содержит **исторические нарративы**, вынесенные из `MEMORY.md`, чтобы держать основной handoff в бюджете (`LC_ALL=en_US.UTF-8 wc -m` ≤ 50 000 символов (НЕ `wc -c` — он считает байты, кириллица = 2 байта) — канон в `.claude/skills/of-end-session/SKILL.md`).
> Файлы здесь читаются **только по запросу** конкретной задачи (не при bootstrap'е). Текст переносится **дословно**: архив — это перенос, а не пересказ.

## Правила использования

- **НЕ грузить эти файлы по умолчанию** в новой сессии. Bootstrap читает только `START.md` + актуальный `MEMORY.md`.
- Использовать когда:
  - Пользователь спрашивает «почему мы сделали X», «когда мы перешли с Y на Z»
  - Нужны детали миграции/фикса конкретной версии
  - Работаешь с legacy-кодом, упоминающим старые конфиги/паттерны
- Альтернатива — `git log --oneline --grep="vX.Y"` если нужна только запись о факте изменения.

## Как добавлять новые архивные записи

Когда `MEMORY.md` выходит за бюджет — выносить сюда. Правило отбора:

- **Остаётся в `MEMORY.md`:** действующие инварианты, ключевые файлы и пути, активные грабли последних версий, навигация по подсистемам — всё, что нужно новой сессии для работы СЕГОДНЯ.
- **Уходит в архив:** детальные нарративы «как мы это делали» по конкретным версиям и детали, уже зафиксированные в `.cursor/rules/*.mdc` или в тематическом `docs/*.md` (правила НЕ дублировать — только ссылка).
- В `MEMORY.md` вместо вынесенного остаётся **одна строка-указатель** на архивный файл + перечень живых правил из этого пласта.
- Архивный файл называть либо по версиям (`vX.Y-vZ.W.md`), либо по теме с диапазоном версий (`vX.Y-vZ.W-<тема>.md`).

Шаблон записи:

```markdown
### vX.Y.Z — короткое название (YYYY-MM-DD)

**Что было**: симптом/проблема (1-2 предложения).
**Что сделали**: ключевой фикс/фича (3-5 строк, упоминаются файлы).
**Грабли**: что не повторить (если есть).
**Ссылка на коммит**: `git log -1 <hash>` или PR.
```
