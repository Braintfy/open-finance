## v0.18.1 — Hotfix Date binding postgres.js

**postgres.js + raw `sql\`...\``: НЕ передавать `Date` через `${}`** — `drizzle-orm/postgres-js` шлёт через `pgClient.unsafe()`, не применяет type-aware serializers → `TypeError: The "string" argument must be of type string ... Received an instance of Date`.

**Решение:** `const fromIso = from.toISOString();` и `WHERE col >= ${fromIso}::timestamp` (или `::date`).

Затрагивает все Ozon-routes (`/api/marketplaces/ozon/{kpi,timeseries,top-ads,abc,campaigns,search-phrases}`, `/api/marketplaces/analytics/ozon`, `/api/unit-economics/products`).

Drizzle insert/update API (`db.insert().values({col: Date})`) работает корректно.

## v0.18.10-v0.18.12 — Analytics + Performance API root-cause fixes

- **НЕ путать `product_id` и Ozon SKU.** `unit_products.article` = seller `offer_id`; `unit_products.sku` должен быть реальным Ozon SKU. `product_id` — только в `metadata.productId`. Баг v0.18.10: `sku = String(info.id)` давал неверные ссылки `ozon.ru/product/{sku}` и ломал join рекламы.
- **Analytics ads join должен быть backward-compatible.** Lateral aggregate по `unit_products.sku`, legacy `metadata.productId`, `offer_id` и raw `Артикул`; не делать прямой `LEFT JOIN agg_ads ON a OR b OR c` без агрегирования — задвоит строки.
- **«Заказы»/выручка не считаются по `status = 'delivered'`.** SQL считает «delivered» = заказы кроме явно отменённых/возвращённых (включая `awaiting_deliver`/`delivering`). Иначе на 7d-окне всё в пути → блок 0 продаж.
- **Отмены/возвраты считать не только по датам.** `cancelled_at`/`returned_at` могут быть null; учитывать `lower(status) LIKE '%cancel%'/'%return%'`.
- **`ozon_perf_sku_stats` с `campaign_id NULL` может дублироваться.** Postgres unique index не дедупит `NULL` → `perfSkuStats` перед записью очищает агрегаты текущего окна.
- **Performance API generate — POST с JSON body, не GET.** Раньше GET → Ozon 400 «Некорректный период» = root cause «реклама не загружается».
- **Sync API принимает `stages` override.** `POST /sync` поддерживает body `{ stages: Record<OzonStageKind, boolean> }`.
- **Дефолтные окна orders/transactions расширены до 90 дней** (было 30).

## v0.18.15 — Multi-endpoint smart routing CPC+CPO

**Корневая разгадка**: `/api/client/campaign` НЕ возвращает `paymentType` — фильтровать по **`adv_object_type`**:

**CPO endpoint** — `GET /api/client/statistics/all_sku_promo/products/generate?timeBounds.from&timeBounds.to`. CSV: дата, статус, расход, продажи_поиск, продажи_реко, заказы_поиск, заказы_реко. **БЕЗ SKU** (per-day per-shop).

**Таблицы**: `ozon_perf_sku_stats(account, date, sku, campaign_id)` + `ozon_perf_cpo_daily(account, date)`. UNIQUE `(account_id, date)`.

**Стейджи**: `perfCampaigns` → `perfSkuStats` (CPC/CPM) → `perfCpoDaily` (CPO) → `perfPhrases`.

## v0.18.18 — Ozon Performance CSV header detection (КРИТИЧЕСКАЯ ЛОВУШКА)

**Грабли, выжгшие 15+ сессий**: Ozon Performance CSV-отчёты НЕ начинаются с header'а — первые 2 строки это **метадата кампании** (`"Кампания N (CPC)"; "01.05.2026-31.05.2026"` + пустая строка), реальный header (`sku;Название;...`) идёт **третьей строкой**. Старый `parseCsv` брал `lines[0]` → header = метадата → все строки выкинуты. Sync завершался `status='success', itemsTotal=409, itemsProcessed=0`. UI: «Расход на рекламу не загружен → Подключите Performance API», хотя API подключён.

**Fix** ([`src/lib/marketplaces/ozon/performance/endpoints.ts:299-336`](../../src/lib/marketplaces/ozon/performance/endpoints.ts)):
- `detectHeaderIndex(lines)` ищет первую строку с известной колонкой из `CSV_HEADER_SIGNALS` (`sku|артикул|дата|расход|показы|клики`). Метадата пропускается.
- `parseCsv` стартует data-loop с `headerIdx + 1`.
- `findKey` поддерживает **prefix match** (`"Расход, ₽, с НДС".startsWith("расход")`).
- `normalizeDate()` понимает оба формата Ozon: ISO `2026-05-19` и RU `19.05.2026`.

**Visibility fix** (silent-failure не маскируется):
- `SyncStageState.warnings?: string[]` — `full.ts` прокидывает в `ozon_sync_jobs.stages.<stage>.warnings`.
- `lastSyncSummary.stages.<stage>` теперь содержит `{ok, itemsProcessed, itemsTotal, warnings, error}`.
- `OzonSyncSection` рендерит `SilentFailureBanner` (красный, если `ok=true && itemsTotal>0 && itemsProcessed=0`) + `SyncSummaryGrid`.
- Блок Аналитики разделяет 3 случая для `adsSource='none'`: (1) `perfConnected=false` → «Подключите Performance API», (2) `silentFailure=true` → «Sync завершился, но Performance отчёты не записаны → debug-script», (3) иначе → «Performance подключён, sync ещё не было».
- `perf-sku-stats.ts`/`perf-cpo-daily.ts` автоматически warning с первыми 200 символами CSV если `processed===0 && rows.length > 0`.

**Diagnostic CLI**: `pnpm tsx scripts/debug-ozon-perf-csv.ts <accountId>` — read-only.

### Cell-binding: useBlockValuePublisher convention

Модалка «Связать ячейку с источником» читает 2 источника:
1. **Live** — `useBlockValuePublisher(instance.id, output)`. Только если блок-источник mounted.
2. **Remote** — `GET /api/blocks/sources` → `fieldsForBlock()`. Cross-page.

**Конвенция publisher'а**:
- `value: <number>` — primary chip.
- `__labels: 'key1=Label1,key2=Label2'` — русские названия.
- `__money: 'field1,field2'` — поля как `1 234 ₽`.

**Грабли**: Ключи publisher'а ДОЛЖНЫ совпадать с `fieldsForBlock` (server-side), иначе live-merge не сработает.
