# Yandex SmartCaptcha — настройка (I6)

Капча защищает формы **входа**, **регистрации** и **сброса пароля** от ботов
(brute-force, спам-регистрации, email-бомбинг). Работает поверх rate-limit (C1).

## Как это устроено

- **Виджет** — `src/components/captcha/smart-captcha.tsx` (грузит `captcha.js`,
  рендерит «я не робот», отдаёт одноразовый токен в форму).
- **Серверная проверка** — `src/lib/security/captcha.ts` (`verifyCaptcha()` шлёт
  токен в Yandex `POST /validate`).
- **Роуты** — `/api/auth/register|login|forgot-password` проверяют токен ПОСЛЕ
  rate-limit и до бизнес-логики.
- **Выключено по умолчанию:** если ключи не заданы — капча пропускается (dev),
  формы работают как раньше.

## Шаги настройки

1. **Yandex Cloud → SmartCaptcha.** Открой консоль:
   `https://console.yandex.cloud` → сервис **SmartCaptcha** → **Создать капчу**.
2. **Домены (Allowed sites).** Добавь домены, где стоит форма: `localhost`
   (для dev), твой прод-домен (`app.example.ru`). Без этого виджет не отрисуется.
3. **Тип:** «Стандартная» (кнопка «я не робот») — рекомендуется. Язык — русский.
4. **Скопируй два ключа:**
   - **Client key** (публичный) — для виджета в браузере.
   - **Server key** (секретный) — для серверной проверки. Не публиковать!
5. **Пропиши в env** (`.env.local` для dev, секреты прод-окружения для прода):

   ```bash
   # Публичный — уходит в браузер, ОБЯЗАТЕЛЬНО префикс NEXT_PUBLIC_
   NEXT_PUBLIC_YANDEX_SMARTCAPTCHA_CLIENT_KEY=ysc1_...
   # Секретный — только на сервере
   YANDEX_SMARTCAPTCHA_SERVER_KEY=ysc2_...
   ```

6. **Пересобери/перезапусти.** `NEXT_PUBLIC_*` вшивается в бандл на этапе сборки —
   после изменения нужен новый `pnpm build` (или перезапуск `pnpm dev`).

## Проверка

- Открой `/login` (или `/register`, `/forgot-password`) — под формой появится
  виджет «я не робот», кнопка submit заблокирована до прохождения.
- Отправь форму — сервер проверит токен; при неуспехе увидишь ошибку и виджет
  сбросится для повторной попытки.
- Убери ключи из env → капча исчезает, формы работают как прежде.

## Поведение и нюансы

- **Fail-open при аварии Yandex:** если сервис `/validate` недоступен или отвечает
  не-200 — запрос пропускается (не блокируем вход из-за их сбоя). Явный вердикт
  «робот» или отсутствие токена — блок.
- **Токен одноразовый, TTL 5 минут.** После ошибочной отправки форма ремонтит
  виджет (через `key`), чтобы пользователь прошёл проверку заново.
- **Только server key — секрет.** Client key публичен по дизайну (он в HTML).
- **Логин на каждый вход:** капча показывается при каждой попытке входа. Если
  нужно «только после N неудач» — это отдельная доработка (сервер возвращает флаг
  needCaptcha, фронт показывает виджет по нему).
