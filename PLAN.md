# Open Finance — AI Финансовый Управляющий

## Миссия
**Дать каждому предпринимателю и фрилансеру персонального AI-финансиста** — уровня топового управляющего, но за доступную цену. Не просто дашборд с цифрами, а **умного советника**, который анализирует, прогнозирует, предупреждает и подсказывает решения.

## Концепция
Облачная SaaS-платформа с **модульным конструктором** — пользователь собирает свою финансовую панель как конструктор из блоков (виджеты, модули, надстройки). AI работает поверх всех данных как единый мозг: видит связи, паттерны и аномалии.

### Ключевые принципы
- **AI-first над всеми данными** — AI работает поверх ВСЕХ данных пользователя как единый разум, не локально по одному модулю
- **Модульный конструктор** — каждый собирает под себя (селлер, фрилансер, ИП, малый бизнес)
- **Доступность** — сложная финансовая аналитика простым языком, понятный UX
- **Прогнозы > отчёты** — фокус на будущее, а не только фиксация прошлого
- **Единое окно** — все деньги в одном месте (МП + банки + касса + налоги)
- **Простая структура для AI агентов** — код и данные организованы так, чтобы любой AI-агент (наш встроенный или внешний типа Claude Code) разбирался за минуты
- **Graceful degradation** — без AI приложение работает как обычная финансовая программа; с AI — становится умным секретарём

2. Бизнес-аналитика МП (unit-экономика, ДРР, ROAS)
3. Полный финучёт РФ (УСН, НДС, КУДИР, P&L)
4. Модульный конструктор (кастомный дашборд под задачу)

**Open Finance = Copilot Money для бизнеса × MPStats финансы × 1С-лайт — всё в одном, с AI.**

## Модульный конструктор (ядро продукта)

### Концепция
Пользователь выбирает модули как блоки конструктора. Каждый модуль — самостоятельный, но AI видит связи между ними.

### Базовые модули (в Free)
- **💰 Денежный поток** — доходы/расходы, баланс, тренд
- **📊 Дашборд** — виджеты drag-n-drop, кастомные графики

### Бизнес-модули (Pro)
- **🏪 Маркетплейсы** — OZON, WB, Яндекс (sync + аналитика)
- **📦 Unit-экономика** — маржа по товару, ДРР, ROAS, себестоимость
- **🧾 Налоги РФ** — все режимы (см. ниже отдельный блок)
- **🏦 Банк** — импорт выписок (Tinkoff, Сбер, Альфа)
- **💳 Платежи** — ЮKassa, Т-Касса, эквайринг, возвраты, СБП
- **🚚 Поставки и закупки** — закупки из Китая, отслеживание грузов, поставщики, ВЭД
- **📋 Заказы и клиенты** — мини-CRM, статусы заказов, источники
- **📅 Планировщик** — задачи, дедлайны, напоминания, GTD-стиль
- **📄 Документы** — УПД, акты, счета, договоры (PDF/XML парсинг)

### AI-надстройки (Pro)
- **🤖 AI Советник** — чат с финансовым ассистентом (Claude/OpenAI/Ollama)
- **🔮 Прогнозы** — cash flow forecast, сезонность, тренды
- **⚠️ Аномалии** — автодетект необычных трат, просадок маржи
- **📋 Авто-категоризация** — ML-классификация операций (>95% точность)
- **💡 Рекомендации** — «сократи расходы на логистику на 12%», «смени тариф УСН»
- **🔍 AI-валидация документов** — проверка УПД на ошибки, сверка с операциями

### Свободные блоки (Free + Pro) — Excel-like мини-модули
**КЛЮЧЕВАЯ ИДЕЯ:** пользователь создаёт свой блок с формулами, как ячейки Excel или базы данных Notion. Идёт **в базовую версию** — это foundation модульного конструктора.

- **🧮 Mini-spreadsheet** — таблица с ячейками и формулами (=SUM, =AVG, =IF, =VLOOKUP)
- **🔗 Cross-references** — ссылки на данные из других модулей (`=marketplace.ozon.revenue`)
- **🤖 AI-помощь в формулах** — «посчитай маржу с учётом комиссии 15%» → AI генерит формулу
- **📋 Шаблоны блоков:**
  - Личный бюджет (доход/расход/сбережения)
  - Поставки с Китая (закупка, доставка, растаможка, продажная цена, маржа)
  - ROI калькулятор (вложил X → получил Y → % годовых)
  - Сравнение поставщиков (цена, сроки, качество, рейтинг)
  - Долги/займы (кому, сколько, дедлайн, процент)
  - Подписки (что, сколько, когда списание)
  - Цели (накопить X к дате Y, прогресс-бар)
- **📐 Кастомные виджеты** — добавить блок на дашборд из своих данных
- **🔄 Auto-recalc** — при изменении источника пересчёт автоматический

### Пользовательские модули (будущее)
- Marketplace модулей от сообщества
- Возможность шарить шаблоны блоков
- Импорт из CSV / Excel / Google Sheets

## Налоговые режимы РФ (модуль «Налоги»)

### Поддерживаемые режимы
**КЛЮЧЕВАЯ ОСОБЕННОСТЬ:** пользователь выбирает режим при настройке + может **сравнить альтернативы** через AI-сценарий.

| Режим | Кому | Ставка | Лимит дохода | Поддержка |
|-------|------|--------|-------------|-----------|
| **УСН «Доходы» 6%** | ИП, ООО | 6% от дохода | 450 млн ₽ (2025) | MVP |
| **УСН «Доходы−Расходы» 15%** | ИП, ООО | 15% от прибыли | 450 млн ₽ | MVP |
| **НДС 5%/7%/20%** | УСН с доходом >60 млн | 5%/7%/20% | — | MVP |
| **ПСН (Патент)** | ИП | Фикс. сумма | 60 млн ₽ | Phase 2 |
| **НПД (Самозанятый)** | Физлицо, ИП | 4%/6% | 2.4 млн ₽ | Phase 2 |
| **АУСН** | ИП, ООО | 8%/20% | 60 млн ₽, до 5 чел | Phase 2 |
| **ОСНО** | ИП, ООО | НДС + НДФЛ/прибыль | — | Phase 3 |
| **ЕСХН** | Фермеры | 6% | — | По запросу |

### Функции модуля
- **Выбор режима** при первой настройке + смена через год
- **Калькулятор налогов** под выбранный режим
- **КУДИР** для УСН/ОСНО/ПСН/ЕСХН (генерация PDF/XLSX)
- **Книга учёта** для НПД, АУСН (упрощённая)
- **Авансовые платежи** — расчёт + дедлайны + напоминания
- **Декларации** — авто-заполнение шаблонов 3-НДФЛ, УСН, НДС
- **Сценарии «Что если»** — AI сравнивает: «при твоём обороте УСН 15% даст экономию 47 200₽ vs УСН 6%»
- **Льготы и вычеты** — авто-учёт страховых взносов ИП, минимальный налог УСН
- **Региональные ставки** — учёт льготных регионов (УСН 1%/5% в некоторых субъектах)
- **История изменений** — налоговые реформы 2025/2026 с уведомлениями

### Roadmap по налогам
1. **MVP:** УСН 6% + УСН 15% + НДС 5% (миграция из `/Users/firay/NALOG`)
2. **Phase 2:** ПСН, НПД, АУСН (для самозанятых и патентщиков)
3. **Phase 3:** ОСНО (для крупных ООО, требует НДС 20% и НДФЛ)
4. **Постоянно:** обновления при налоговых реформах

## AI-функциональность (детально)

### 1. Предиктивный анализ (вдохновлено Copilot Money)
Не «ты потратил X», а «при текущем темпе ты превысишь бюджет на Y к концу месяца».
- Прогноз cash flow на 30/60/90 дней
- Предупреждение о кассовых разрывах
- Сезонные паттерны (сравнение год-к-году)

### 2. Финансовый коучинг (вдохновлено Cleo)
AI даёт конкретные actionable советы простым языком:
- «Твоя маржа на товаре X упала на 8% за месяц — проверь закупочную цену»
- «Через 15 дней авансовый платёж УСН ~34 200₽ — отложи сейчас»
- «Расходы на рекламу WB выросли на 23%, но продажи только на 5% — пересмотри ставки»

### 3. Автокатегоризация (вдохновлено Monarch Money)
ML-модель на истории операций:
- Автоматическая разметка входящих транзакций
- Обучение на корректировках пользователя
- Правила + ML гибрид (>95% точность после 2 недель)

### 4. Сценарное моделирование (новый пункт, добавлено из анализа)
**Почему:** Monarch Money показал, что пользователи хотят «что если» сценарии. Для бизнеса это ещё важнее.
- «Что если поднять цену на 10%?» — пересчёт маржи, прогноз продаж
- «Что если добавить новый товар?» — оценка ROI
- «Что если перейти на НДС 5%?» — сравнение налоговых режимов

### 5. Smart-уведомления (новый пункт, добавлено из анализа)
**Почему:** Cleo доказал — nudge-уведомления меняют финансовое поведение. Для бизнеса это critical.
- Telegram / Email / Push
- Настраиваемые триггеры (маржа < X%, расход > Y, кассовый разрыв через Z дней)
- Дайджест: утренний (что было вчера) + недельный (итоги)

### 6. Inbox — drop-папка для AI (КЛЮЧЕВАЯ ФИЧА)

**Идея:** у пользователя есть **«входящая папка»** (физическая или виртуальная), куда он бросает что угодно — сканы чеков, скриншоты, PDF договоров, текстовые заметки, Excel-таблицы, фото. AI-агент **раз в день** (или по триггеру) проверяет папку, парсит содержимое и **сам создаёт модули, блоки, транзакции, напоминания**.

#### Где живёт Inbox
- **SaaS:** S3-bucket пользователя (`inbox/{userId}/`) + UI кнопка «Загрузить файлы»
- **Local-First:** локальная папка `~/OpenFinance/Inbox/` (можно настроить путь)
- **Mobile:** share extension — поделиться чем угодно из любого приложения в Open Finance Inbox
- **Email-to-Inbox:** уникальный адрес `inbox.{user}@openfinance.ru` — переслать письмо туда

#### Что AI делает с содержимым
| Тип файла | Действие |
|-----------|---------|
| Чек / Receipt (фото) | OCR → транзакция в `expenses` с категорией |
| PDF договор | Извлечение сторон/сумм/дат → запись в `documents` + дедлайны |
| Excel-таблица | Импорт в Excel-блок или создание нового модуля |
| Текстовая заметка | Парсинг намерения → планировщик / напоминание / блок |
| Скриншот переписки | Извлечение задач/обещаний → планировщик |
| Голосовая запись | Whisper → текст → парсинг → действия |
| Email forwarded | Парсинг отправителя/темы → транзакция или документ |

#### Режимы работы
- **Auto-mode (по умолчанию)** — AI сам всё разносит, пользователь видит дайджест «Я добавил 5 транзакций, 1 поставку, 2 напоминания. Открыть? / Откатить?»
- **Approve-mode** — AI готовит черновики, показывает «Я нашёл это, добавить?» — пользователь утверждает
- **Per-type-rules** — например, чеки авто, договоры — approve

#### Ежедневная проверка
- Cron job в `workers/inbox-watcher.ts` — раз в день в настроенное время
- При попадании нового файла — мгновенный fs.watch (Local) или S3 event (SaaS)
- Уведомление в Telegram/Email: «Я обработал 3 файла из Inbox, посмотри»

### 7. AI-секретарь — интеграция с коммуникациями

**Идея:** AI получает доступ (с явного разрешения пользователя) к **почте, контактам, мессенджерам**, чтобы понимать **контекст**, находить **связи** (например, «в чате с Игорем обсуждали поставку — вот её детали»), создавать **напоминания** автоматически.

#### Источники
| Канал | Что берём | Технология |
|-------|----------|-----------|
| **Email** | Письма с заказами, счетами, договорами | IMAP / Gmail API / Outlook Graph |
| **Telegram** | Личные чаты, рабочие группы, каналы | Bot API + MTProto (через user-аккаунт) |
| **WhatsApp** | Бизнес-переписка | WhatsApp Business API (Meta Cloud API) |
| **VK** | Сообщения, переписка | VK API (мессенджер) |
| **MAX (российская)** | Чаты | API когда появится публичный |
| **Контакты** | Имена, компании, ИНН | iCloud / Google Contacts / CardDAV |
| **Календарь** | Встречи как контекст | Google Calendar / iCloud / CalDAV |

#### Принципы приватности (важно!)
- **Opt-in** — каждый канал подключается явно, можно отключить в один клик
- **Granular access** — можно выбрать «только чаты с тегом #работа», или конкретные группы
- **Local processing где возможно** — на Local-First версии Whisper / парсинг идут локально, наружу уходят только финансовые выводы
- **No storage of raw messages** — храним только embeddings + извлечённые сущности (заказ, сумма, дата), не весь текст переписки
- **Полное удаление** — кнопка «Стереть всё что AI знает обо мне» в settings
- **Audit log** — пользователь видит ВСЁ что AI сделал на основе коммуникаций

#### Что AI с этим делает
- **Связывает чаты с заказами** — «в чате с @ivan обсуждали заказ на 47 000₽, оплата через неделю» → создаёт ожидание прихода
- **Распознаёт контрагентов** — «Игорь Иванов из @logistics_group = поставщик ИП Иванов И.И.»
- **Создаёт напоминания** — «через неделю проверить оплату от Игоря»
- **Находит документы** — «договор с этой компанией был в email от 2024-03-15, прикрепить?»
- **Пишет отчёты** — «по заказу #042: переписка → согласование → оплата → отгрузка → доставка»

#### Roadmap по интеграциям
- **Phase 1:** Email (IMAP), Telegram (Bot API)
- **Phase 2:** Telegram MTProto (личный аккаунт), Google Contacts
- **Phase 3:** WhatsApp Business, VK
- **Phase 4:** MAX (когда API), iCloud Contacts/Calendar
- **Future:** «как Open Claw» — оркестратор всех каналов с возможностью отвечать (write access)

## AI-first архитектура (КРИТИЧНО)

**Принцип:** AI — это **первоклассный гражданин**, а не дополнение. Архитектура спроектирована так, что:
1. AI имеет единое представление обо всех данных пользователя (через RAG)
2. AI может действовать (создавать, редактировать, удалять) с подтверждением пользователя
3. Структура кода и БД проста и предсказуема, чтобы внешние AI-агенты (Claude Code, Cursor) могли в неё легко погружаться

### Слои AI

```
┌─────────────────────────────────────────────────┐
│  AI Orchestrator (агент-оркестратор)            │
│  ────────────────────────────────────────────   │
│  • Выбирает модель (Claude / OpenAI / Ollama)   │
│  • Управляет инструментами (tools)              │
│  • Логирует действия (audit log)                │
└────────┬────────────────────────────────────────┘
         │
    ┌────┴───────────────────┐
    ▼                        ▼
┌────────────────┐   ┌────────────────┐
│  Memory Layer  │   │  Tools Layer   │
│  (RAG-система) │   │  (действия)    │
│                │   │                │
│ • pgvector     │   │ • create_block │
│ • semantic     │   │ • create_txn   │
│   search       │   │ • create_remi… │
│ • context      │   │ • run_formula  │
│   window mgmt  │   │ • parse_file   │
└────────┬───────┘   └───────┬────────┘
         │                   │
         └─────────┬─────────┘
                   ▼
           ┌──────────────┐
           │  User Data   │ ← все модули проекта
           │  (Drizzle DB)│
           └──────────────┘
```

### Memory Layer (RAG)

**Технология:** PostgreSQL + **pgvector** (extension) + Drizzle ORM

#### Схема (упрощённо)
```typescript
import { pgTable, uuid, text, vector, timestamp } from "drizzle-orm/pg-core";

export const memoryChunks = pgTable("memory_chunks", {
  id: uuid().defaultRandom().primaryKey(),
  tenantId: uuid("tenant_id").notNull(),
  source: text("source").notNull(),     // 'inbox', 'transaction', 'chat', 'document'
  sourceId: uuid("source_id"),          // ref к оригиналу
  content: text("content").notNull(),   // нормализованный текст
  embedding: vector("embedding", { dimensions: 1536 }), // OpenAI ada / Claude / local
  metadata: jsonb("metadata"),          // tags, dates, amounts
  createdAt: timestamp("created_at").defaultNow(),
}).enableRLS();

// HNSW индекс для быстрого ANN-поиска
// CREATE INDEX ON memory_chunks USING hnsw (embedding vector_cosine_ops);
```

#### Гибридный поиск (Hybrid Search)
- **Семантический** — `embedding <=> query_embedding` (cosine distance)
- **Полнотекстовый** — `tsvector @@ to_tsquery(...)` (русская морфология)
- **Слияние через RRF** — Reciprocal Rank Fusion (best of both worlds)
- **Фильтры** — по `tenantId` (RLS), по `source`, по датам, по тегам

#### Что хранится как embeddings
- Тексты транзакций (категория, описание, контрагент)
- Заметки и блоки пользователя
- Извлечённые из коммуникаций факты («Игорь обещал оплатить 15 числа»)
- Документы (УПД, договоры) — chunked
- История диалогов с AI
- Готовые инсайты («в марте маржа упала на 8%»)

### Tools Layer

**Принцип:** AI не пишет SQL и не дёргает Drizzle напрямую. Он использует **типизированные инструменты** — функции с JSON-схемами.

```typescript
// src/lib/ai/tools/index.ts
export const aiTools = [
  {
    name: 'create_transaction',
    description: 'Создать запись о транзакции (доход/расход)',
    parameters: zodToJsonSchema(z.object({
      amount: z.number(),
      category: z.string(),
      description: z.string(),
      date: z.string().datetime(),
      type: z.enum(['income', 'expense']),
    })),
    handler: async (args, ctx) => createTransaction(args, ctx.tenantId),
  },
  {
    name: 'create_reminder',
    description: 'Создать напоминание с дедлайном',
    parameters: { /* ... */ },
    handler: async (args, ctx) => createReminder(args, ctx.tenantId),
  },
  // ... остальные tools
];
```

**Все мутации идут через tools.** Это даёт:
- Audit log (кто/что/когда — log table)
- Откат (каждое действие имеет inverse)
- Безопасность (RLS + tenant_id в context)
- Проверка прав (free-tier не может звать `create_marketplace_sync`)

### Управление контекстным окном

Проблема: транзакций тысячи, всё не влезает в контекст LLM.

**Решение:** многоуровневая память (как в [A Practical Guide to Memory for LLM Agents](https://towardsdatascience.com/a-practical-guide-to-memory-for-autonomous-llm-agents/)):

| Уровень | Что | Когда подгружается |
|---------|-----|------------------|
| **Working memory** | Текущий запрос + последние 10 сообщений диалога | Каждый запрос |
| **Episodic** | Релевантные транзакции/блоки через RAG (top-K=10) | Семантический поиск по запросу |
| **Semantic** | Профиль пользователя (тариф, налоговый режим, активные модули) | Каждый запрос |
| **Procedural** | Tools schemas, system prompt | Каждый запрос (статично) |

**Compression:** при заполнении контекста на 80% — суммаризация старых сообщений в episodic memory.

### VPN-надстройка для зарубежных AI API

**Проблема:** OpenAI/Anthropic API в РФ блокируются на уровне провайдера.

**Решение:** встроенная VPN-надстройка (Vless / WireGuard) в админке:
- Админ вставляет Vless-ссылки набора серверов в панели управления
- AI Orchestrator роутит запросы выбранному AI-провайдеру через эти серверы (только их, не весь трафик)
- Поддержка пула серверов с round-robin / fail-over
- Мониторинг: latency по каждому серверу, успешность реквестов
- Альтернатива: HTTPS proxy / SOCKS5 из того же ЛК
- **Расположение:** `src/lib/ai/transport.ts` — абстракция HTTP-транспорта (axios + tunnel agent)

**Детали:** продумаем позже (Протокол/формат хранения ссылок, сбор фидбэка).

## AI-агенты + счётчик токенов (Phase 2-3, опция)

### Идея
**AI-помощник = единый разум.** Но у него внутри могут жить **специализированные агенты**, которых пользователь сам создаёт или включает. Это как «нанять отдел сотрудников».

### Примеры агентов
| Агент | Что делает | Триггер |
|-------|-----------|--------|
| **Price Watcher** | Каждый день проверяет цены конкурентов на твои товары на МП | Ежедневно по cron |
| **Margin Guard** | Следит за маржой ниже X%, предупреждает | На каждую транзакцию |
| **Tax Optimizer** | Раз в квартал проверяет налоговый режим — может ли быть выгоднее | Quarterly |
| **Cashflow Forecaster** | Прогноз кассового разрыва на 30/60/90 дней | Еженедельно |
| **Inbox Sorter** | Парсит файлы в Inbox-папке (см. секцию выше) | Daily |
| **Communications Reader** | Читает почту/чаты, извлекает заказы и контакты | Hourly |
| **Reporter** | Генерит еженедельный/ежемесячный отчёт | Weekly/Monthly |
| **Research** | По запросу ищет информацию (поставщики, цены, альтернативы) | По запросу |

### Skills (специализации)
Агент может иметь **набор skills** — это композируемые умения:
- `read_marketplace_prices` — может вытаскивать цены с OZON/WB
- `parse_invoice` — умеет парсить счета
- `generate_report_pdf` — собирает PDF
- `send_telegram` — пишет в Телеграм пользователю
- `query_database` — делает RAG-запрос

**Two режима выбора скилов:**
1. **Manual:** пользователь сам выбирает скилы из библиотеки при создании агента
2. **Auto:** AI анализирует задачу («создай агента который...») → подбирает скилы → показывает на утверждение

### Счётчик токенов (важно для контроля!)

**Зачем:** AI стоит денег. Без контроля — пользователь может случайно потратить $100 за день.

#### Что показываем
- **В реальном времени** в шапке: `Сегодня: 42 500 токенов / 0.84 $`
- **График по дням/неделям** в settings → Usage
- **Лимиты per agent:** «Price Watcher тратит до 1000 токенов/день»
- **Лимит global per tariff:**
  - Free / Trial: 10K токенов/день, потом graceful disable AI
  - Pro: 100K токенов/день
  - Business: 500K токенов/день
  - Enterprise: безлимит

#### Storage
```typescript

  id: uuid().defaultRandom().primaryKey(),
  tenantId: uuid('tenant_id').notNull(),
```

#### Защита от перерасхода
- **Pre-flight check** — перед каждым AI-запросом проверка лимита

- **Уведомление** при достижении 80% дневного лимита
- **Cost estimation** — перед запуском дорогой операции («это займёт ~1500 токенов / 0.03 $»)

## Tauri vs Electron — окончательный выбор: **Tauri 2.0**

### Сравнительная таблица

| Критерий | Tauri 2.0 | Electron | Что лучше для нас |
|----------|-----------|----------|------------------|
| Размер бандла | ~3-10 MB | ~80-150 MB | **Tauri** |
| RAM idle | ~50-80 MB | ~150-250 MB | **Tauri** |
| Старт приложения | ~0.4-0.8 s | ~1.5-3 s | **Tauri** |
| Безопасность | Rust + sandboxed WebView | Chromium full | **Tauri** (Rust = меньше surface) |
| WebView движок | OS native (WebKit/WebView2) | Bundled Chromium | Tauri (но менее консистентно) |
| Mobile поддержка | iOS + Android (v2) | ❌ | **Tauri** |
| Auto-updater | Встроен | Нужно настраивать | **Tauri** |
| Sidecar binaries | Native поддержка (Rust) | Через child_process | **Tauri** |
| Доступ к API ОС | Через Rust commands (typed) | Node API | Tauri (typed RPC) |
| Зрелость | Young (v2 из 2024) | Mature (с 2013) | Electron |
| Скорость разработки | Чуть медленнее (Rust для нативных кусков) | Быстрее (Node везде) | Electron |
| AI Engine локально (Ollama) | Через sidecar | Через child_process | Equal |

### Почему Tauri выигрывает для Open Finance
1. **Размер** — пользователю не качать 150 MB ради финансовой программы
2. **RAM** — Open Finance может работать в трее весь день, важно мало жрать
3. **Mobile единая база кода** — Tauri 2.0 даёт iOS+Android из той же кодовой базы
4. **Безопасность** — финансы → меньше surface attack
5. **WebView2 на Windows** — встроен в Win10/11, не нужно качать отдельно

### Минусы Tauri (учитываем)
- Меньше готовых плагинов (Electron mature ecosystem) — пишем свои на Rust
- Команда должна знать минимум Rust (для нативных модулей)
- WebKit на macOS / WebView2 на Windows / WebKitGTK на Linux — могут быть мелкие различия рендера

### Альтернатива (на крайний случай)
Если Tauri не справится в Phase 2 — backup план:
- **Electron** — если нужна сложная нативная интеграция с офисными пакетами
- **Native Swift/Kotlin** — для премиум desktop опыта (но тогда раздельная команда)

**Решение:** Tauri 2.0, мобильная версия идёт через React Native + Expo (отдельная база, шарим бизнес-логику через `packages/core/`).

### Выбор ORM: Drizzle ORM (вместо Prisma)

**Что выбрано:** **Drizzle ORM** — type-safe TypeScript ORM с прямым SQL-контролем.

**Почему Drizzle лучше для Open Finance:**

| Критерий | Prisma | Drizzle | Преимущество |
|----------|--------|---------|--------------|
| Размер бандла | ~13 MB | ~7.4 KB | Drizzle ×1700 меньше |
| Производительность | Query Engine (Rust) | Прямой SQL | Drizzle быстрее в 2-5× |
| Serverless / Edge | Cold start ~300ms | Zero deps, ~10ms | Drizzle для Vercel/Cloudflare |
| RLS (multi-tenant) | Через middleware | Нативная `.enableRLS()` | Drizzle проще для SaaS |
| Type safety | Schema → generated | TypeScript-first | Drizzle строже типизирует |
| SQLite (локально) | Поддерживается | Поддерживается | Равно |
| Миграции | `prisma migrate` | `drizzle-kit` | Равно, обе хороши |
| Кривая обучения | Низкая (DSL) | Средняя (SQL) | Prisma проще для junior |

**Решение:** Drizzle. Главные причины:
1. **Одна кодовая база для SaaS (Postgres) и Local (SQLite)** — Drizzle переключается через драйвер, без изменения схемы
2. **Нативная RLS** для multi-tenant SaaS
3. **Edge-ready** — если будем выносить часть API на Cloudflare Workers
4. **Serverless cold start** — критично для Free-тарифа (масштабирование без затрат)
5. **Прямой SQL** — для финансовых отчётов нужны сложные агрегации

## Локальная версия (Local-First) — для приватности

### Зачем нужна

### Платёжные шлюзы (биллинг)

**Стратегия:** **двойная резервируемость** — если один шлюз упадёт или заблокируют, переключаемся на резервный без даунтайма.

#### Основной: Т-Касса (Tinkoff/Т-Бизнес)
- **Что:** интернет-эквайринг + рекуррентные платежи (подписки)
- **API:** `https://www.tbank.ru/kassa/develop/`
- **Покрытие:** карты МИР/Visa/Mastercard, СБП, Tinkoff Pay, Yandex Pay
- **Особенности:**
  - Рекуррентные платежи через rebill-токен после первой оплаты
  - Webhooks на статусы (Authorized / Confirmed / Rejected / Refunded)
  - Чек online-кассы автоматически (54-ФЗ)
  - Поддержка фискализации через aQsi/Эвотор
- **Ставки:** 1.99-2.49% за транзакцию (карта), 0.4-0.7% (СБП)

#### Резервный: CloudPayments
- **Что:** альтернативный эквайринг с фокусом на SaaS-подписки
- **API:** `https://developers.cloudpayments.ru/`
- **Покрытие:** карты + Apple Pay + Google Pay + СБП
- **Особенности:**
  - Сильная поддержка рекуррентов (нативные «планы подписки»)
  - Без редиректа (форма открывается на сайте)
  - Splitting платежей (если будем делать партнёрскую программу)
  - Виджет на JS — быстрая интеграция за день
- **Ставки:** ~2.7% за транзакцию

#### Третий вариант (зарезервировано на будущее)
- **YooKassa (Яндекс)** — если понадобится широкое покрытие розничных карт
- **Robokassa** — для агрегации мелких платежей
- **Stripe** (если выйдем на международный рынок)

## Дедлайны и напоминания (cross-cutting feature)

### Принцип
**Любой блок, любой модуль может иметь дедлайн.** Это не отдельный модуль, а слой поверх всех остальных. Как в Notion — у любой записи можно добавить дату + напоминание.

### Где используется
| Модуль | Примеры дедлайнов |
|--------|-----------------|
| Налоги | Авансовый платёж УСН (25 апреля), декларация (30 апреля) |
| Поставки с Китая | Оплата поставщику, прибытие в порт, растаможка, доставка на склад |
| Заказы клиентов | Дата отгрузки, ожидание оплаты, гарантийные сроки |
| Планировщик | GTD-задачи, проекты, ревью |
| Документы | Истечение договора, сроки актирования |
| Подписки (Excel-блок) | Списание Notion, Claude API, домен, хостинг |
| Цели (Excel-блок) | «Накопить 500к к декабрю» — прогресс + дедлайн |

### Функции
- **Дедлайн на любом блоке** — клик «добавить дату» в любой записи (как Notion `/date`)
- **Повторения** — каждый месяц / квартал / год (для налогов и подписок)
- **Многоуровневые напоминания** — 30 / 14 / 7 / 3 / 1 день / в день
- **Каналы:** in-app banner, Telegram, Email, push (Tauri/PWA)
- **AI-приоритизация** — «3 важных дедлайна на неделю» в утреннем дайджесте
- **Календарный вид** — все дедлайны на месяц в виде календаря (`/calendar`)
- **Экспорт в iCal** — синхронизация с Apple Calendar, Google Calendar

### Пример: модуль «Поставки с Китая»
Блок поставки содержит подмодули с дедлайнами:
```
📦 Поставка #042 (футболки oversize)
├── Поставщик: Guangzhou Textile Co.
├── 💰 Оплата 1 (50%): 15.05.2026 ⏰ через 3 дня
├── 🚢 Отгрузка из порта: 28.05.2026
├── 🛃 Растаможка: ~10.06.2026 (плановая)
├── 💰 Оплата 2 (50%): при доставке
├── 📅 Прибытие на склад: 18.06.2026
└── 🏪 Запуск продаж: 22.06.2026
```
Каждая строка — дедлайн с напоминанием. AI помогает: «Запас на складе кончится 15.06, а партия только 18.06 — будет 3 дня без товара, рассмотри ускоренную логистику».

## Дизайн и UX (вдохновлено Notion, Linear, Claude Code, Codex)

### Философия
**«Сложное — простым».** Финансы — стрессовая тема. Интерфейс должен снимать стресс, а не добавлять его. Минимум визуального шума, максимум clarity.

### Ключевые UX-принципы (из лучших продуктов)

#### Из Notion
- **Slash-команды (`/`)** — добавить блок/виджет/модуль в любом месте через `/`
- **Block-based интерфейс** — каждый виджет = блок, drag/drop/duplicate/delete
- **Inline editing** — клик на любое поле редактирует на месте, без модалок
- **`@mentions`** — связать с другим модулем/блоком: `@OZON.выручка`
- **Templates** — шаблоны блоков и страниц одним кликом

#### Из Linear (как опция, не как основа)
**Принцип:** изначально всё через **мышь и drag-n-drop** — это интуитивно для большинства пользователей. Keyboard shortcuts — **продвинутая опция** для power-users, открывается через подсказки и onboarding.

- **Командная палитра (`Cmd+K`)** — опциональный быстрый доступ к действиям и поиску. Видна как кнопка в шапке, открывается и кликом мыши.
- **Скорость** — мгновенный отклик, оптимистичные UI updates (важно для всех, не только клавиатурщиков)
- **Чистая типографика** — Inter / SF Pro, контраст 60-70%
- **Подсказки shortcuts** — при hover над кнопкой видно `⌘K`, в settings отдельная страница «Горячие клавиши»
- **Прогрессивное раскрытие** — pop-up «Знаете, что это можно сделать через `⌘N`?» после 5-го клика по «Добавить транзакцию»

#### Из Obsidian
- **Local-first** — нет интернета — всё работает
- **Markdown везде** — заметки в любом блоке поддерживают markdown
- **Графовая визуализация** — связи между модулями (наш ReactFlow mindmap)
- **Plugin-архитектура** — модули как плагины (наша концепция)

#### Из Claude Code / Codex (idol-tier UX)
- **Минимализм** — убраны все decorative элементы, только функциональные
- **Светлая тема по умолчанию** (большинству привычнее для финансов) + тёмная опция
- **Контекстная подсветка** — то что важно — выделено, остальное приглушено
- **Прогресс прозрачен** — статус операций виден в реальном времени
- **Гармония типографики** — один шрифт, 3-4 размера, 2-3 веса
- **Spacing система** — кратные 4px/8px (4, 8, 16, 24, 32, 48, 64)

### Дизайн-система

**Палитра (минимализм):**
- Background: `#FAFAFA` (light — по умолчанию) / `#0A0A0A` (dark)
- Foreground: `#0A0A0A` / `#EDEDED`
- Muted: `#737373`
- Primary (action): `#3B82F6` (синий, как Linear/Codex)
- Success: `#10B981`
- Warning: `#F59E0B`
- Danger: `#EF4444`

**Система тем:**
- **Светлая — по умолчанию** (лучше для финансов, привычнее большинству)
- Тёмная / Auto (system) — переключается в settings
- Реализация — глобальные CSS-переменные + Tailwind `dark:` модификатор + `next-themes`
- Без дублирования кода — все цвета идут через CSS variables (`--bg`, `--fg`, `--muted` и т.д.)

**Типографика:**
- Шрифт: **Inter** (UI) + **JetBrains Mono** (числа, формулы, код)
- Размеры: 12 / 14 / 16 / 20 / 24 / 32 (6 уровней, не больше)
- Веса: 400 (regular), 500 (medium), 600 (semibold)

**Spacing:** базовая сетка 4px, шаги 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64

**Иконки:** Lucide (единый стиль, 16/20/24 px)

### Платформы

#### Web (адаптивный)
- Desktop: трёхколоночный layout (sidebar + content + AI panel)
- Tablet: двухколоночный (sidebar collapsible)
- Mobile: одна колонка, bottom navigation, оптимизированные виджеты

#### Desktop (Tauri 2.0)
- Нативный titlebar (или кастомный с translucent background на macOS)
- System tray иконка
- Глобальные shortcuts (Cmd+Shift+O — открыть приложение)
- Drag-n-drop файлов из Finder/Explorer

#### Mobile (Native app в приоритете)
**Решение:** Native app (React Native + Expo) — основная mobile-платформа.

- Почему native: native push, share extension (для Inbox из любого приложения), Face ID/Touch ID, biometrics, лучший UX
- React Native + Expo + NativeWind (Tailwind для RN) — разделяем UI-логику с вебом
- React Native Skia для графиков
- Expo Router (файловый роутинг как Next.js)
- PWA остаётся как fallback для тех кто не хочет устанавливать приложение

### Анимации (сдержанные, как Linear)
- Длительность: 150-250ms (не дольше)
- Easing: `cubic-bezier(0.4, 0, 0.2, 1)` (Material standard)
- Не злоупотреблять — только смысловые переходы

### Accessibility
- Контраст WCAG AA (минимум)
- Keyboard navigation на 100% (без мыши работает всё)
- Screen reader labels на всех action-элементах
- Focus rings (видимые, не убираем для дизайна)

## Добавленные пункты из анализа конкурентов

### Из Copilot Money (рейтинг #1 AI-финансов)
- **Предиктивный cash flow** — прогноз баланса на 30/60/90 дней, предупреждение о кассовых разрывах
- **Авто-категоризация >95%** — ML на истории + обучение на корректировках пользователя
- **Чистый UI** — минимализм, фокус на actionable инсайты, а не на перегрузку данными

### Из Cleo (вирусный рост через coaching)
- **Финансовый коучинг** — AI говорит простым языком, даёт конкретные советы («сократи X на Y%»)
- **Nudge-уведомления** — поведенческие триггеры, которые реально меняют привычки
- **Доступный тон** — не «финансовый отчёт», а «привет, вот что важно сегодня»

### Из Monarch Money (для семей и планирования)
- **Сценарное моделирование** — «что если» для бизнес-решений
- **Долгосрочные проекции** — не только месяц, но 3-6-12 месяцев
- **Multi-user** — владелец + бухгалтер + менеджер видят разное

### Из Notion (block-based revolution)
- **Slash commands** `/` — добавление блоков и виджетов везде
- **Block editor** — каждая запись = блок с возможностями
- **Inline editing** — никаких модалок, всё редактируется на месте
- **`@mentions`** — связывание модулей и блоков ссылками
- **Templates** — готовые шаблоны блоков (бюджет, поставки, ROI)

### Из Linear (скорость + keyboard-first)
- **`Cmd+K` palette** — всё через клавиатуру за секунды
- **Оптимистичные UI updates** — действие → мгновенный отклик
- **Минимализм** — никаких лишних элементов, чистая типографика

### Из Obsidian (local-first + связи)
- **Local-first режим** — Tauri + SQLite, всё работает офлайн
- **Markdown везде** — заметки в любом блоке
- **Plugin-архитектура** — модули как плагины (наша концепция)
- **Граф связей** — наш ReactFlow mindmap

### Из Claude Code / Codex (idol-tier минимализм)
- **Светлая тема по умолчанию** + тёмная опция через CSS-переменные
- **Контекстная подсветка** — важное выделено, остальное приглушено
- **Гармония типографики** — Inter + JetBrains Mono, 6 размеров max

### Оригинальные идеи Open Finance
- **AI-first архитектура** — AI работает поверх ВСЕХ данных через RAG (pgvector), а не локально по модулю
- **Модульный конструктор** — ни один конкурент не даёт собирать свой дашборд из блоков
- **Excel-like блоки в базовой версии** — мини-spreadsheet с формулами и шаблонами
- **Inbox — drop-папка для AI** — кидаешь что угодно, AI само разносит (как личный ассистент)
- **AI-секретарь** — связь с email/TG/WA/VK/MAX для понимания контекста и связей
- **Налоги РФ нативно** — все режимы (УСН/НДС/ПСН/НПД/АУСН/ОСНО) с возможностью сравнения
- **Кросс-платформенная аналитика** — все МП + банки + касса в одном месте
- **Local-first + Cloud** — пользователь выбирает режим под свой уровень paranoia
- **Дедлайны на любом блоке** — поставки, налоги, цели, подписки — всё в едином календаре
- **Двойная резервируемость биллинга** — Т-Касса + CloudPayments переключаются runtime
- **AI-friendly структура кода** — простая, плоская, с CLAUDE.md/AGENTS.md для onboarding любого AI-агента
- **Безлимитная история на Free** — никаких ограничений по времени даже на бесплатном тарифе
- **Trial Pro без карты** — после регистрации кнопка «Попробовать», 14 дней Pro без оплаты
- **AI-агенты с настраиваемыми скилами** — пользователь создаёт «отдел сотрудников» под свои задачи (Phase 2)
- **Счётчик токенов в шапке** — пользователь всегда видит сколько потратил, защита от перерасхода
- **Встроенная VPN-надстройка** — для работы с зарубежными AI API (Claude/OpenAI) без отдельного VPN на устройстве
- **BYOK (Bring Your Own Key)** — пользователь может вставить свой API-ключ AI-провайдера и не платить нам за токены
