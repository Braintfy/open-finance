# Задача: оптимизация загрузки контекста проекта

## Цель
Снизить расход токенов на «прогрев» новой AI-сессии в 5–10 раз без потери качества понимания проекта. Перейти от загрузки больших контекстных файлов целиком (CHANGELOG, PLAN, docs) к ленивой загрузке через единый bootstrap-файл и таблицу маршрутизации «по типу задачи → какие файлы читать».

## Что нужно сделать (по этапам)

### Этап 1. Аудит текущего состояния (только чтение, без изменений)

Найди и оцени:

1. **Все always-applied правила** проекта — какие файлы автоматически попадают в каждую сессию через workspace rules / `CLAUDE.md` / `AGENTS.md` / `.cursor/rules/` / `.cursorrules`. Замерь их суммарный размер.
2. **Контекстные файлы**, которые правила требуют читать перед задачей: `MEMORY.md`, `CHANGELOG.md`, `PLAN.md`, `ROADMAP.md`, `docs/*` и т.п. Подсчитай строки/токены каждого.
3. **Дубли и устаревшие файлы**:
   - один и тот же файл в нескольких местах (например, `CLAUDE.md` в корне проекта и в родительской папке)
   - файлы со стека «прошлой жизни» проекта (старая БД, старый фреймворк), которые противоречат актуальным правилам
4. **Семантическую память** (если используется MemPalace, mem0, Letta, локальная RAG-БД и т.п.) — работает ли индекс, нет ли в нём массово устаревших версий проекта, которые будут давать misleading контекст при поиске.
5. **Структуру `src/`** проекта — главные модули, их назначение, ключевые точки входа.
6. **`package.json`** / `pyproject.toml` / `Cargo.toml` — стек, версии, скрипты.
7. **Последние 30 коммитов** (`git log --oneline -30`) — текущая фаза проекта, что делалось недавно.

Сохрани в голове (или выпиши): сколько токенов сейчас грузится «по умолчанию» в новую сессию, что из этого устарело, что дублируется.

### Этап 2. Создать `START.md` в корне проекта

Это **единственный файл**, который AI должен прочитать первым в новой сессии. Размер — строго ~100–150 строк (~1.5–2K токенов). Структура (адаптируй под проект):

```markdown
# START.md — bootstrap-контекст <ИМЯ ПРОЕКТА>

> Единственный файл, который AI читает первым в новой сессии.
> Триггер пользователя: «загрузи контекст <короткое имя>» или «прогрев <короткое имя>».
> Остальная документация подгружается по запросу задачи, не по умолчанию.

## Что делать в новой сессии (3 шага, ~6–8K токенов)
1. Прочитать этот START.md.
2. Прочитать MEMORY.md (или его аналог — компактный handoff).
3. Запустить `git -C <абсолютный путь к репо> log --oneline -20`.

## Идентичность
2–4 строки: что это за проект, для кого, главная архитектурная идея, текущая фаза.
Источник правды по статусу: <MEMORY.md / CHANGELOG.md / другое>; package.json версия может отставать.

## Жёсткие правила (MUST NOT)
Список из 8–15 запретов: что нельзя делать (git auto-commit, прод-миграции, секреты в коммите, запрещённые библиотеки, обязательные паттерны и т.п.).

## Стек (1 строка)
Перечисли через `+`: frontend, backend, БД, кеш, ключевые библиотеки, версии Node/Python.

## Структура src/ (или аналог)
ASCII-tree на 10–20 строк, по одной строке на ключевую папку с комментарием «что тут лежит».

## Маршрутизация: какую задачу — какие файлы читать
Таблица из 10–20 строк, формат:
| Тип задачи | Что читать (только это, не всё подряд) |
Примеры строк (адаптируй):
- Новый API endpoint → ...
- Изменение DB schema → ...
- Auth / сессии → ...
- Биллинг → ...
- Стратегия / roadmap → PLAN.md через Read offset+limit, не файл целиком
- История релизов → `git log` или CHANGELOG.md offset+limit, не файл целиком
- Работа с библиотекой X → Context7 / web docs (max 3 запроса)

## Команды
Блок bash: установка, dev, проверка (typecheck/lint/build), тесты, БД-команды.

## После значимых изменений (обязательно)
Чек-лист: build → обновить MEMORY.md (если поменялись ключевые файлы) → CHANGELOG → команды git для пользователя (не выполнять самому).

## Семантическая память (если используется)
Статус индекса, использовать ли на старте, или только точечно через search.

## Ключевые грабли (не повторять)
Список из 5–10 пунктов с конкретными подводными камнями проекта.
```

**Важно:** `START.md` должен быть самодостаточным — после его чтения агент должен сразу понимать, что и где искать дальше. Никаких отсылок «см. главу 4 PLAN.md».

### Этап 3. Переписать существующие файлы правил под ленивую загрузку

Найди все «always-applied» файлы правил проекта (обычно `CLAUDE.md`, `AGENTS.md`, `.cursorrules` или их эквиваленты) и в каждом:

1. **Замени** обязательное чтение `MEMORY.md → CHANGELOG.md → PLAN.md → docs/*` на:
   ```
   Bootstrap новой сессии (триггер пользователя — «загрузи контекст <имя>»):
   1. START.md (~1.5K токенов)
   2. MEMORY.md (~5K токенов)
   3. git log --oneline -20
   ```

2. **Добавь явный список «не загружать по умолчанию»**:
   - `CHANGELOG.md` — только при вопросе про историю; иначе `git log`
   - `PLAN.md` / `ROADMAP.md` — только при стратегических вопросах, и только нужный раздел через `Read offset+limit`
   - семантический поиск (mempalace/mem0/etc) — только точечно по конкретному вопросу, не как стартовый контекст (если индекс содержит устаревшие версии)
   - `docs/*` — каждый файл подгружается, только когда задача его касается

3. **Сохрани секцию «после значимых изменений»** — обновлять MEMORY/CHANGELOG/START.md (если меняются bootstrap-инварианты), синхронизировать внешние handoff-файлы.

4. **Удали дубли правил**: если найдены устаревшие копии файла правил в родительских папках или копии от прошлой версии проекта — удали их. Это самая большая утечка токенов.

### Этап 4. Обновить `MEMORY.md` (компактный handoff)

В шапке `MEMORY.md`:

1. Обнови «Быстрый старт для AI-агента» — поставь те же 3 шага bootstrap (`START.md` → `MEMORY.md` → `git log`).
2. Добавь явный блок «Что НЕ загружать по умолчанию» — синхронно с тем, что в `CLAUDE.md`/`AGENTS.md`.
3. В секции «файлы, которые AI должен знать» добавь пометки про каждый файл: грузится автоматически (через workspace rules) / читается на bootstrap / только по запросу.
4. Обнови секцию «текущий статус» — поставь свежую версию.

### Этап 5. Опционально — внешние AI-handoff и семантическая память

Если проект используется во внешних AI-сервисах (ChatGPT, Gemini, отдельные Cursor/Cline-сессии без доступа к репо):

1. Найди/создай зеркало контекста (типа `~/.mempalace/sources/<project>/current-context.md` или `docs/AI_HANDOFF.md`) — обнови по тому же шаблону, что и `START.md`, но с встроенной полной таблицей маршрутизации (внешний AI не может читать репо).
2. Удали дубли (старые версии того же файла в разных местах).

Если используется семантическая память (MemPalace/mem0/etc):

1. Проверь, что индекс жив (`mempalace status` / эквивалент). Если сломан — почини (миграция/переиндексация).
2. Если индекс содержит много устаревших версий проекта — **исключи его из bootstrap** (явно напиши в правилах: использовать только точечно через `search`, не как стартовый контекст).
3. Перемайнь актуальный код, чтобы свежие файлы попали в топ результатов поиска.

### Этап 6. Записать изменения в `CHANGELOG.md`

Добавь запись с bump'ом версии (PATCH-инкремент). Формат:

```markdown
## [X.Y.Z] - YYYY-MM-DD

### Added
- **`START.md`** — компактный bootstrap-файл (~1.5K токенов): идентичность, жёсткие правила, стек, структура `src/`, таблица маршрутизации «по типу задачи → какие файлы читать», команды, ключевые грабли. Единственный файл, который AI читает первым в новой сессии.

### Changed
- **Bootstrap-процесс** — `<правила-файлы>` переведены с тяжёлой обязательной загрузки `MEMORY.md` + `CHANGELOG.md` + `PLAN.md` целиком на ленивую загрузку: `START.md` + `MEMORY.md` + `git log -20`. Стартовый контекст ужат с ~XK до ~6–8K токенов без потери качества.
- `CHANGELOG.md` / `PLAN.md` по запросу — больше не грузятся целиком по умолчанию.
- <семантическая память — статус и решение>

### Removed
- <устаревшие дубли правил>
```

### Этап 7. Финальная проверка

1. Линт изменённых .md (если есть markdownlint) — должен пройти.
2. Покажи пользователю:
   - Список изменённых/созданных/удалённых файлов.
   - Цифры «было токенов на старте → стало токенов на старте».
   - **Команду-триггер** для новой сессии (одной фразой).
   - Готовые `git add / commit / push` команды (НЕ выполняй сам — выведи как блок для копирования).

## Жёсткие правила выполнения

- НЕ делай `git add/commit/push` — давай команды пользователю.
- НЕ выполняй DB-миграции — давай команды.
- Используй `Read` для чтения файлов целиком (или с offset+limit для больших), НЕ `cat`/`head`/`tail`.
- Используй `Grep`/`Glob` вместо `find`/`grep` в shell.
- Если в проекте семантическая память даёт устаревшие данные — лучше исключить её из bootstrap, чем тащить misleading контекст.
- Перед удалением дублей обязательно убедись, что это именно дубль (не уникальный контент).

## Критерии готовности

- [ ] Создан `START.md` в корне проекта (~100–150 строк).
- [ ] Все always-applied правила обновлены: bootstrap = `START.md` + `MEMORY.md` + `git log -20`, остальное — по запросу.
- [ ] Удалены устаревшие дубли файлов правил.
- [ ] Шапка `MEMORY.md` обновлена под новый bootstrap.
- [ ] Запись в `CHANGELOG.md` добавлена с bump'ом PATCH-версии.
- [ ] Линт-проверка пройдена.
- [ ] Пользователю выведены: список изменений, метрика «было/стало токенов», команда-триггер, готовые git-команды.

## Команда для пользователя в новой сессии (после выполнения этой задачи)

> «загрузи контекст <короткое имя проекта>»

или

> «прогрев <короткое имя>»

Этого должно быть достаточно, чтобы агент за 6–8K токенов получил полный контекст и был готов к работе любой сложности.
