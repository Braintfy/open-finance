# deploy/pi-status — консоль состояния на локальном мониторе

Воткнул монитор в Raspberry Pi — сразу видно, что с сервером: живо ли приложение, что со связью, питанием, температурой, базой и синхронизациями. Без логина, без сети, без интернета.

## Что показывает

| Раздел | Содержимое |
|---|---|
| Приложение | версия (из сборки, не из `CHANGELOG`), код ответа сайта, состояние `open-finance` / `nginx` / `docker` / `xray` — **с пометкой, если сервис работает, но без автозапуска** |
| Железо | температура, троттлинг и просадки питания (`vcgencmd get_throttled`), память, нагрузка, аптайм, занятость диска и **на чём стоит корень: microSD или NVMe** |
| Сеть | адрес, состояние Ethernet, SSID + уровень сигнала + канал Wi-Fi, работоспособность VPN-прокси для AI |
| База | Postgres, размер базы, **активные синхронизации Ozon** (при них перезагружать нельзя — job повиснет), время последней сборки, ошибки в журнале за сутки |

Цвета: зелёный — норма, жёлтый — внимание, красный — проблема.

## Установка

```bash
sudo install -o root -g root -m 0755 deploy/pi-status/of-status.sh /usr/local/bin/of-status
sudo install -o root -g root -m 0644 deploy/pi-status/of-console-status.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl disable --now getty@tty1.service     # освобождаем первую консоль
sudo systemctl enable --now of-console-status.service
```

## Как этим пользоваться

- **Монитор в HDMI** — сразу открывается дашборд, обновляется каждые 5 секунд.
- **Нужен логин с этого же монитора** — `Alt+F2` (или F3–F6): systemd поднимет обычную консоль по требованию (`NAutoVTs=6` по умолчанию). Дашборд остаётся на `Alt+F1`.
- **По SSH** — команда `of-status` даёт тот же снимок один раз, `of-status --loop` — в режиме обновления.

## Почему getty убран с tty1

Иначе логин-приглашение и дашборд дерутся за экран и затирают друг друга. Логин никуда не делся — он доступен на других виртуальных консолях по `Alt+F2`, плюс SSH.

Вернуть как было:
```bash
sudo systemctl disable --now of-console-status.service
sudo systemctl enable --now getty@tty1.service
```

## Особенности, заложенные в проверки

- **VPN проверяется по `api.anthropic.com`, а не по `api.ipify.org`.** Через этот outbound ipify рвёт TLS, хотя туннель исправен — индикатор врал бы. Успех — код `401` (достучались, но без ключа); `403` означает гео-блок, то есть VPN не работает.
- **Проверка прокси делается дважды.** Туннель периодически роняет отдельные соединения (замерено: примерно одно из пяти), одна неудача не должна показывать красное.
- **Версия берётся из `.next/required-server-files.json`**, то есть из фактически собранного кода, а не из `CHANGELOG.md`. Так видно рассинхрон «в репозитории новая версия, а на сервере крутится старая сборка».
- **Скрипт ничего не меняет** — только читает. Юнит запущен от `firay` с `ProtectSystem=strict` и `ProtectHome=read-only`.

## Сторож сети (`of-net-watchdog`)

Решает конкретную проблему: после включения питания Wi-Fi иногда не ассоциируется, и плату приходится перезагружать руками.

**Лестница вмешательств** — перезагрузка только как крайняя мера:

| Через | Что делает |
|---|---|
| ~2 мин без сети | перезапуск `NetworkManager` |
| ~4 мин | переподнятие интерфейсов (`nmcli disconnect/connect`) |
| ~8 мин | **перезагрузка платы**, но не больше 3 раз |

**Почему есть лимит.** Без него при поломке роутера плата уйдёт в вечный цикл перезагрузок, и до неё нельзя будет достучаться даже когда сеть вернётся. После исчерпания лимита сторож продолжает следить и писать в журнал, но не перезагружает. Счётчик **обнуляется сам**, когда сеть стабильно продержалась 10 минут — то есть инцидент считается закрытым.

**Что ещё учтено:** первые 3 минуты после старта система не трогается (даём догрузиться); перед перезагрузкой проверяется, не идёт ли синхронизация Ozon — у неё нет корректного завершения, job повиснет.

**Живость сети определяется по шлюзу, а не по интернету.** При падении провайдера перезагружать плату бессмысленно — проблема не в ней.

```bash
sudo install -o root -g root -m 0755 deploy/pi-status/of-net-watchdog.sh /usr/local/sbin/
sudo install -o root -g root -m 0644 deploy/pi-status/of-net-watchdog.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now of-net-watchdog
```

Пороги меняются в `Environment=` внутри юнита, а не в скрипте. Состояние — `/var/lib/of-net-watchdog/` (счётчик и последнее действие), они же видны в дашборде строкой «сторож сети». Журнал: `journalctl -u of-net-watchdog`.

## Известное ограничение консоли

Часть кириллицы на мониторе отображается квадратами: ядро Pi 5 отказывается подгружать шрифты в DRM-консоль (`setfont: Unable to load such font with such kernel version`) при любом наборе и размере. Цифры, статусы и латиница читаются нормально. Радикальное решение — перевести подписи дашборда на латиницу.

## Управление вентилятором (`of-fan`)

Вентилятор Argon ONE V3 висит на **шине I2C корпуса (адрес `0x1a`)** и управляется одним байтом — процентом оборотов. Штатное управление Raspberry Pi OS его не видит: оно рассчитано на фирменный активный кулер.

Требуется `dtparam=i2c_arm=on` в `/boot/firmware/config.txt`, модуль `i2c-dev` и пакет `i2c-tools` — **шина активируется только после перезагрузки**. Проверка, что корпус на связи: `sudo i2cdetect -y 1` → в строке `10:` должен быть `1a`.

```bash
sudo install -o root -g root -m 0755 deploy/pi-status/of-fan.sh /usr/local/sbin/
sudo install -o root -g root -m 0644 deploy/pi-status/of-fan.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now of-fan
```

Кривая по умолчанию: до 50 °C тишина, 55 → 30%, 62 → 50%, 68 → 70%, 75 → 100%. Меняется в `Environment=` юнита.

**Две вещи, на которых легко обжечься:**

1. **Кавычки вокруг `FAN_CURVE` обязательны.** systemd делит `Environment=` по пробелам, и без кавычек до скрипта доедет только первая пара порогов — вентилятор молчал бы при любой температуре. Поймано на живом сервере по строке в журнале.
2. **При выходе служба ставит 55%, а не 0.** Если скрипт упадёт, лучше пусть шумит, чем перегревает.

Снижение оборотов идёт с гистерезисом (по умолчанию 3 °C), иначе вентилятор «пилит» на границе порога — это слышно сильнее ровного шума. Текущее состояние — `/run/of-fan.state`, оно же строкой «вентилятор» в дашборде.

**Что считать нормой:** у Pi 5 троттлинг начинается около 80-85 °C. Замеры на этом сервере: 42-48 °C в простое, 54 °C под полной нагрузкой на четыре ядра. Тёплый корпус — это правильно: алюминий работает радиатором и отводит тепло наружу.
